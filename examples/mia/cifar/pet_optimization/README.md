# PET optimization on CIFAR-10

Traces the **utility-vs-attack-success frontier** for DP-SGD on a small CIFAR-10
CNN: train the model many times under different privacy settings, attack each
one the same way, and see what privacy costs in accuracy.

## Prerequisites

The campaign reads `examples/mia/cifar/data/cifar10.pkl`, which is **not in the
repository** — it is generated by the CIFAR example notebook. Run
`examples/mia/cifar/cifar_main.ipynb` (the data-preparation cells are enough)
before the first campaign, or you will get a bare `FileNotFoundError` here.

## Running it

```bash
# pipeline check: 2 configs, 2 epochs, 1 reference model — minutes, not hours
python run_campaign.py --smoke

# a real sweep
python run_campaign.py --n-configs 50 --epochs 15

# include the non-private anchor (an explicit noise=0 point, index -1)
python run_campaign.py --n-configs 50 --include-nonprivate
```

**Cost.** One configuration = 1 target model + `--n-refs` reference models, all
trained from scratch. The defaults (50 configs, 2 references) are **150 full
trainings**. Start with `--smoke`.

## Output

Everything lands in `--out` (default `leakpro_output/pet_optimization`):

| File | What it is |
|---|---|
| `evaluations.jsonl` | one JSON line per evaluated configuration — the campaign's state, and what resume reads |
| `campaign.json` | the run's identity (seed, proxy FPR, knob space); resuming with different settings is refused |
| `run_meta.json` | epochs/refs/seed, cross-checked by `validate_frontier.py` |
| `frontier.png` | scatter of every configuration with the Pareto front highlighted |

Interrupted runs resume: rerun the same command and finished configurations are
skipped. A configuration that raises is recorded with an `error` field and
retried on the next run rather than killing the sweep.

## Reading a record

```json
{"index": 3, "config": {"noise_multiplier": 1.8, "max_grad_norm": 0.9, ...},
 "epsilon": 4.21, "utility": 0.517,
 "attack_tpr": 0.0312, "attack_tpr_events": 62, "attack_tpr_n": 2000,
 "attack_tpr_ci95": [0.024, 0.040], "attack_realized_fpr": 0.0100,
 "attack_threshold": 2.27, "attack_resolution_warning": null}
```

- `utility` — test accuracy.
- `attack_tpr` — attack success at the proxy operating point (1% false-alarm
  rate). **Lower is safer.**
- `attack_realized_fpr` — the false-alarm rate actually achievable in the data.
  If it is far below the requested one, `attack_resolution_warning` explains
  that the number is interpolated rather than observed: treat it as unresolved,
  not as evidence of privacy.
- `attack_tpr_ci95` — binomial sampling error over audit points **only**. It
  does not include target-training randomness or the reference draw, which are
  plausibly larger.
- `attack_skipped: "utility_gate"` — the model did not beat the chance floor, so
  attacking it would have measured nothing; no attack was run.

## Validating the frontier

The loop optimizes a deliberately cheap proxy. Before trusting a frontier point,
re-measure it with a stronger attack and a larger audit set:

```bash
python validate_frontier.py --campaign-dir leakpro_output/pet_optimization \
    --epochs 15 --seed 0
```

`--epochs` and `--seed` must match the campaign's (checked against
`run_meta.json`; a mismatch is refused, because a different seed reshuffles
every split and a different epoch count is a different model). The output adds
`selection_bias` — the gap between the loop's TPR and the revalidated one, which
is the direct measure of how optimistic the search was.
